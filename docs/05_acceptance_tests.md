# Acceptance Tests (Validation vs Intended Use)

驗收測試對應 00_intended_use.md 中的「預期用途」，確保系統實現快速 CSV 查詢、支援複雜條件的核心承諾。

---

## 1. 基本查詢場景 (Basic Query Scenario)

**AT-01: 單條件精確匹配**

*預期用途*：「高效能數據檢索，支援即時查詢」

測試步驟：
1. 載入包含 100,000 名學生記錄的 CSV（欄位：ID, Name, Grade, Age）
2. 執行查詢：`SELECT * FROM students WHERE ID = '12345'`
3. 驗證結果中只有一筆記錄，ID 正確

驗收標準：
- 查詢延遲 < 50ms
- 結果精確度 100%
- 記憶體使用 < 500MB

---

## 2. 複合條件場景 (Complex Conditions Scenario)

**AT-02: AND 邏輯查詢**

*預期用途*：「支援類 SQL 複合查詢語法」

測試步驟：
1. 載入學生記錄 CSV
2. 執行查詢：`SELECT Name, Age FROM students WHERE Grade = 'A' AND Age < '20'`
3. 驗證結果集中所有記錄 Grade = 'A' 且 Age < '20'
4. 記錄查詢延遲與結果數量

驗收標準：
- 查詢延遲 < 100ms（即使結果集 > 1,000 筆）
- 結果集精確度 100%

---

**AT-03: OR 邏輯查詢**

*預期用途*：「支援靈活的條件組合」

測試步驟：
1. 載入城市數據 CSV（欄位：CityID, Name, Province）
2. 執行查詢：`SELECT * FROM cities WHERE Province = 'Taiwan' OR Province = 'Japan'`
3. 驗證結果集僅包含 Province 為 'Taiwan' 或 'Japan' 的記錄

驗收標準：
- 查詢延遲 < 100ms
- 結果集精確度 100%

---

**AT-04: 混合 AND/OR 查詢**

*預期用途*：「複雜謂詞過濾」

測試步驟：
1. 載入學生記錄 CSV
2. 執行查詢：`SELECT * FROM students WHERE (Grade = 'A' OR Grade = 'B') AND Age >= '18'`
3. 驗證結果邏輯正確性

驗收標準：
- 執行無誤
- 結果精確度 100%

---

## 3. 效能場景 (Performance Scenario)

**AT-05: 大檔案快速查詢**

*預期用途*：「處理大檔案並支援即時查詢」

測試步驟：
1. 生成 1,000,000 行的 CSV 測試檔
2. 系統載入檔案並建立索引，記錄耗時
3. 執行 10 個隨機查詢，記錄每個查詢延遲
4. 計算平均查詢延遲

驗收標準：
- 檔案載入時間 < 5 秒
- 平均查詢延遲 < 50ms
- 系統可用記憶體充足（無 OOM）

---

**AT-06: 大結果集返回**

*預期用途*：「即時回應」

測試步驟：
1. 載入包含 50,000 行的 CSV
2. 執行寬泛查詢，預期結果 > 10,000 筆
3. 記錄結果收集與渲染耗時

驗收標準：
- 結果收集耗時 < 100ms
- 記憶體使用合理（< 2GB）

---

## 4. 邊界情況 (Edge Cases)

**AT-07: 空結果集**

測試步驟：
1. 執行無匹配結果的查詢
2. 驗證系統返回空結果集（非錯誤）

驗收標準：
- 系統不崩潰
- 返回空結果明確告知

---

**AT-08: 全記錄匹配**

測試步驟：
1. 執行匹配所有記錄的查詢（例如 `WHERE 1=1`）
2. 驗證返回完整數據集

驗收標準：
- 結果數量 = 總行數
- 無遺漏或重複

---

## 5. 驗收檢查清單

- [ ] AT-02 通過：AND 邏輯正確

- [ ] AT-04 通過：混合邏輯正確
- [ ] AT-05 通過：大檔案快速加載與查詢
- [ ] AT-06 通過：大結果集高效返回
- [ ] AT-07 通過：邊界情況處理穩健
- [ ] AT-08 通過：全集匹配無誤
