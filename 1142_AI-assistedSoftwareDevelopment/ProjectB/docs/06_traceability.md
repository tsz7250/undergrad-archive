## 覆蓋度分析

### 功能需求覆蓋度：100%
- 所有 5 項功能需求 (SRS-F001~F005) 都有對應設計模組、單元測試與驗收測試

### 效能需求覆蓋度：100%
- O(1) 查詢 (SRS-P001) → 設計 (M003, M005) + 單元測試 (UT-03, UT-06) + 驗收 (AT-01)
- 大檔案支援 (SRS-P002) → 設計 + 壓力測試 (ST-02, ST-03) + 驗收 (AT-05, AT-06)
- 記憶體優化 (SRS-P003) → 設計 + 壓力測試 + 驗收

### 使用者需求覆蓋度：100%
- CLI 介面與輸出格式都在集成與驗收測試中驗證

### 約束覆蓋度：~80%
- 技術約束（C++、csv-parser、CSV 格式）透過開發過程內置驗證
- 記憶體限制透過壓力測試與驗收測試確認

## 缺陷追蹤連結

若開發過程中發現缺陷，應記錄對應的：
1. 失敗的測試項目（例如 UT-03 失敗）
2. 對應的 SRS 需求（例如 SRS-F002）
3. 修復所在的設計模組（例如 SDS-M003）

例如：
- **缺陷 #1**：UT-03 失敗，Hash Index 未正確處理重複值
  - SRS ID：SRS-F002
  - Module：SDS-M003
  - 修復：索引鍵值對應邏輯
